# LRN-042 — Faux positifs agents review liés à des erreurs dans les prompts d'agents

| Pattern observé                                                                                                                                                                                                            | Contexte                                                                                                                                            | Application future                                                                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Un doublon accidentel de code dans le prompt de l'Edge Case Hunter génère un finding "critical" inexistant (ECH-1 : double `const result`) ; une description incorrecte du STATE_MAPPING génère ECH-12 (désync ClawdState) | Review Story 2.3 — le prompt ECH contenait `const result = {}` deux fois et un STATE_MAPPING avec des valeurs obsolètes (`coding`, `sad`, `eating`) | Vérifier la cohérence du contenu copié dans les prompts agents (diff exact + fichiers source corrects) avant dispatch — un copier-coller mal aligné génère des faux positifs coûteux à trier |

## Détail

Les 2 faux positifs critiques de l'ECH étaient des artefacts du prompt, pas du code :

- **ECH-1** : le prompt contenait `const result = {} as Record...` deux fois → finding "double déclaration, crash immédiat" → inoffensif, absent du vrai fichier
- **ECH-12** : le prompt montrait un STATE_MAPPING avec `coding/sad/eating/unknown` alors que les fichiers réels contiennent `working/error/notification/waking` → finding "désync critique" → faux, les fichiers sont alignés

**Règle pratique :** pour l'Edge Case Hunter, toujours copier le diff réel (sortie `git diff`) et lire les fichiers source actuels plutôt que les reconstruire de mémoire dans le prompt.
