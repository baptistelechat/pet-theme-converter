# LRN-034 — `catch {}` sans binding → propager `err.message` pour les erreurs filesystem

| Pattern observé                                                                                                                                                                                                                                                                                                                    | Contexte                                               | Application future                                                                                                                                                 |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Un bloc `catch {}` qui écrase toutes les erreurs sous un message générique (ex. "Fichier introuvable") est activement trompeur quand l'erreur réelle est `EACCES` (permission refusée) ou `EISDIR` (répertoire au lieu d'un fichier). L'utilisateur cherche un fichier inexistant alors que le problème est les droits ou le type. | Review Story 2.1 — P3 (fetchFromLocal catch générique) | Toujours écrire `catch (err) { throw new FetchError(\`...: ${err instanceof Error ? err.message : String(err)}\`) }` pour les erreurs I/O exposées à l'utilisateur |
