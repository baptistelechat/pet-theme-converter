## Pattern observé

`apngasm-bin` postinstall bloqué par pnpm → `vendor/apngasm.exe` absent au runtime, ENOENT.

## Détail

`apngasm-bin` utilise `BinWrapper` : le binaire est distribué dans `vendor/win/x64/apngasm.exe` (dans le repo npm) mais `BinWrapper.path()` retourne `vendor/apngasm.exe` (racine du dossier). Le script `lib/install.js` (`bin.run([])`) est responsable de ce déploiement via le hook `postinstall`. Si pnpm bloque les scripts postinstall (comportement par défaut dans certaines configs ou si `--ignore-scripts` est passé), le binaire n'est pas déployé et l'import retourne un chemin inexistant.

**Fix :** exécuter manuellement `node lib/install.js` dans le dossier du package `node_modules/.pnpm/apngasm-bin@x.x.x/node_modules/apngasm-bin/`.

**Symptôme :** `spawn <path>/vendor/apngasm.exe ENOENT` à la première invocation de `execFileAsync(apngasm, [...])`.

## Contexte

Story 2.4 — premier run de `execFileAsync(apngasm, ...)` après implémentation de `encode-apngs.ts`.
