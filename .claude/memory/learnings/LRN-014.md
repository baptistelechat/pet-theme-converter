# LRN-014 — Ne jamais corriger une mémoire sur témoignage verbal seul — vérifier par observation directe

| Pattern observé                                                                                                                                                                 | Contexte                                                                       | Application future                                                                                                                                                                    |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| LRN-005 a été incorrectement "corrigé" quand Baptiste a affirmé "Python fonctionne bien sur mon PC", puis restauré quand `python3 --version` a retourné le stub Microsoft Store | Session `/bmad-create-story` — discussion sur l'absence de Python dans le PATH | Avant de modifier une entrée mémoire existante, vérifier la réalité par observation directe (commande, lecture de fichier, test) — jamais sur la base d'une affirmation verbale seule |

**Règle dérivée :** une mémoire "stale" n'est pas nécessairement fausse. Avant de la corriger, exécuter le test qui permettrait de trancher (ex. : `python3 --version`, lecture d'un fichier de config, vérification d'une dépendance). Si le test échoue, la mémoire originale était correcte.
