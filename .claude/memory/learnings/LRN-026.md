# LRN-026 — Story documentaire pure : vérification par lecture ACs, pas par build

| Pattern observé                                                                                                                                                              | Contexte                                | Application future                                                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Une story qui ne produit que du Markdown (CONTRIBUTING.md, README.md) n'a pas de `pnpm build` à lancer. La vérification des ACs est une lecture manuelle du fichier produit. | Story 1.3 — création de CONTRIBUTING.md | Pour Story 4.2 (README.md) et toute future story purement documentaire, indiquer explicitement dans les Dev Notes "pas de pnpm build requis" et fournir une checklist de lecture ACs. |

## Détail

L'agent dev, habitué aux stories 1.1 et 1.2 qui se concluent par `pnpm build` + `pnpm typecheck`, pourrait par réflexe chercher à compiler après avoir créé CONTRIBUTING.md. L'ajout d'une section de vérification manuelle explicite (tableau de cases à cocher) dans les Dev Notes prévient ce réflexe.

Le skeleton copier-coller (voir [LRN-024](../learnings/LRN-024.md)) s'applique aussi aux stories documentaires : fournir le Markdown complet en Dev Notes réduit l'implémentation à un `Write` direct, sans décision éditoriale laissée à l'agent.
