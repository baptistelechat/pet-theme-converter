# LRN-036 — Protocole de test Core I/O : toujours couvrir URL ET chemin local explicitement

| Pattern observé                                                                                                                                                                                                                                                                            | Contexte                                                                                                                                                                           | Application future                                                                                                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Pour toute fonction Core avec un dispatch URL/local (comme `fetchSpritesheet` + `detectGrid`), les Dev Notes doivent inclure des sources de test des DEUX types — URL distantes ET fichiers locaux téléchargés au préalable. Sans cela, un des deux chemins reste non validé manuellement. | Story 2.2 — Baptiste a demandé d'ajouter des tests avec fichiers locaux (1 `.webp` + 1 `.png`) en plus des 6 URLs de référence Petdex. La story initiale ne couvrait que les URLs. | Stories 2.3/2.4+ : inclure dans les Dev Notes une commande `curl` pour télécharger des fichiers de test locaux et une séquence de validation explicite pour le chemin local. Pattern applicable à toute story Core qui lit un fichier depuis disque ou réseau. |

## Protocole standard à inclure dans les Dev Notes

```bash
# Télécharger les fichiers de test locaux (supprimer après validation)
curl -L -o test-sprite.webp "<URL_webp>"
curl -L -o test-sprite.png  "<URL_png>"
```

Puis valider avec les deux sources dans le même bloc de test :

```ts
// Test URL
const bufferUrl = await fetchSpritesheet(URL);
await nextFunction(bufferUrl);

// Test local
const bufferLocal = await fetchSpritesheet("./test-sprite.webp");
await nextFunction(bufferLocal);
```
