# LRN-049 — `onProgress` ratio : appel APRÈS opération avec `(i+1)/total` pour atteindre 1.0

| Pattern observé                                                                                                                            | Contexte                                                               | Application future                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Appeler `onProgress` avant l'opération avec `i/total` émet de 0 à (n-1)/n — jamais 1.0. Appeler APRÈS avec `(i+1)/total` émet de 1/n à 1.0 | P2 review Story 2.4 — AC3 `ProgressCallback @param progress 0–1` violé | Systématiser le pattern "après + offset+1" pour tous les callbacks de progression dans le pipeline Core |

## Détail

`ProgressCallback` est documentée `@param progress 0–1`. Pour respecter le contrat :

**Pattern à éviter (appel avant, ratio sans offset) :**

```ts
for (let i = 0; i < items.length; i++) {
  onProgress?.(label, i / items.length); // émet 0/n, 1/n, ..., (n-1)/n → jamais 1.0
  await processItem(items[i]);
}
```

**Pattern correct (appel après, ratio avec offset +1) :**

```ts
for (let i = 0; i < items.length; i++) {
  await processItem(items[i]);
  onProgress?.(label, (i + 1) / items.length); // émet 1/n, 2/n, ..., n/n = 1.0
}
```

Le label peut rester en "Encoding APNG: state" même en appel post-opération — il décrit l'étape qui vient de se terminer, ce qui est cohérent avec une barre de progression.
