# LRN-048 — `const` + `await` dans boucle `for` : TDZ dans `finally` si l'initialisation throw

| Pattern observé                                                                                                                                                            | Contexte                                                                                             | Application future                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Déclarer `const v = await asyncCall()` dans une boucle — si `asyncCall` throw, `v` est en TDZ (jamais assigné) et le `finally` ne peut pas y accéder sans `ReferenceError` | P1 review Story 2.4 — `const tempDir = await mkdtemp(...)` hors `try`, finally faisait `rm(tempDir)` | Toujours utiliser `let v: T \| undefined` avant le `try`, avec `if (v)` guard dans `finally` |

## Détail

En JavaScript, `const v = await asyncCall()` à l'intérieur d'un bloc (boucle, scope) : si la partie droite throw, le binding `v` est en **Temporal Dead Zone** — il n'est jamais assigné. Le bloc `finally` est exécuté malgré l'exception, mais toute référence à `v` lèvera `ReferenceError`, **masquant l'erreur originale**.

**Pattern à éviter :**

```ts
const tempDir = await mkdtemp(...); // throw → tempDir en TDZ
try { /* ... */ }
finally { await rm(tempDir, ...); } // ReferenceError → masque l'erreur mkdtemp
```

**Pattern correct :**

```ts
let tempDir: string | undefined;
try {
  tempDir = await mkdtemp(...);
  /* ... */
} finally {
  if (tempDir) await rm(tempDir, { recursive: true, force: true });
}
```
