# LRN-041 — Pattern `sharp(buffer)` une fois + `.clone()` + `Promise.all` frame-level pour la découpe Core

| Pattern observé                                                                                                                                                                                                                        | Contexte                                                                                                                        | Application future                                                                                     |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Pour extraire N frames d'une même source : créer `sharpBase = sharp(buffer)` une seule fois hors des boucles, puis utiliser `sharpBase.clone()` dans un `Promise.all(Array.from({length: frames}, ...))` pour paralléliser frame-level | Story 2.3 review — D1 (réinstanciation 64×) + D3 (séquentiel) résolus opportunistement en combinant `.clone()` et `Promise.all` | Appliquer ce pattern à toute future fonction Core qui extrait plusieurs régions d'un même buffer image |

## Détail

**Avant (64 instanciations séquentielles) :**

```ts
for (let frameIndex = 0; frameIndex < frames; frameIndex++) {
  const frameBuffer = await sharp(buffer).extract({...}).png().toBuffer();
}
```

**Après (1 instanciation + clones parallèles) :**

```ts
const sharpBase = sharp(buffer);
result[state] = await Promise.all(
  Array.from({ length: frames }, (_, frameIndex) =>
    sharpBase.clone().extract({...}).png().toBuffer().catch(...)
  )
);
```

**Pourquoi `.clone()` et pas `sharp(buffer)` à chaque fois :** `.clone()` partage la référence au buffer source en mémoire sans re-créer une instance liée au buffer. Les 8 frames d'un état sont soumises simultanément au thread pool libuv, réduisant le temps total par état.

**Pourquoi garder les états séquentiels :** `onProgress` doit s'invoquer dans l'ordre des états pour que la barre de progression CLI soit cohérente.
