# BDR-015 — Findings de code review dans un fichier dédié `reviews/`, pas dans le story file

| Décision                                                                                                                                                                 | Pourquoi                                                                                                           | Alternatives considérées                                                                   | Statut |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ | ------ |
| Écrire les findings dans `_bmad-output/implementation-artifacts/reviews/<epic-slug>/review-<story-slug>.md` et mettre uniquement un lien de référence dans le story file | Le story file devient illisible avec les findings ; la navigation est plus claire avec un fichier dédié par review | Écrire dans le story file (rejeté — pratique d'un projet précédent, prouvée problématique) | actif  |

Convention de nommage : `review-<story-slug>.md` dans le sous-dossier epic.

Lien obligatoire dans le story file, immédiatement après `Status` :

```markdown
> 📋 **Review :** [reviews/<epic-slug>/review-<story-slug>.md](../../reviews/...)
```
