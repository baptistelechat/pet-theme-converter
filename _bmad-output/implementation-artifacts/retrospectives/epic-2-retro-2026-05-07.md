## Ce qui a été difficile

### 1. Bug frames vides — invisible aux tests automatisés (point critique)

**Fait :** Post-implémentation Story 2.4, Baptiste inspecte visuellement les APNGs générés et détecte un flash blanc. L'inspection des chunks PNG révèle `acTL num_frames=7` au lieu de 8, et une frame `1×1` fantôme (delta-optimisation apngasm sur frames identiques/vides).

**Cause racine :** Le `STATE_MAPPING` avait `frames: 8` pour tous les états après la correction de Story 2.2 — ce qui était "correct" selon la spec disponible. La vérité terrain est que les frames Petdex sont **non uniformes par état** : 6/8/8/4/5/8/6/6/6. Cette information n'est accessible que par inspection manuelle des spritesheets réelles.

**Impact :** Les 75 tests de Story 2.4 (magic bytes + chunk acTL) passaient tous. Sans la validation visuelle de Baptiste, Epic 3 aurait consommé un `STATE_MAPPING` faux et livré des animations corrompues dans le ZIP final.

**Leçon structurante :** La validation visuelle sur artefacts empiriques n'est pas un bonus — c'est une étape nécessaire du pipeline de livraison. Les tests automatisés ne peuvent pas attraper ce qu'ils ne savent pas chercher. LRN-046, LRN-047, BDR-022.

### 2. `apngasm-bin` ENOENT — postinstall bloqué par pnpm (BLK-011)

Le script postinstall de `apngasm-bin` (`node lib/install.js`) n'a pas été exécuté par pnpm. Le binaire natif `vendor/apngasm.exe` n'était pas déployé. L'erreur ENOENT n'apparaissait qu'au runtime — TypeScript était content, le build était vert, le chemin importé était une string valide. Résolu par `node lib/install.js` manuel. LRN-044.

**Implication CI :** Le workflow GitHub Actions (Story 4.1) devra explicitement exécuter ce script ou vérifier la résolution du postinstall sur les 3 OS.

### 3. TDZ dans `finally` — bug de portée JS subtil (P1 Story 2.4)

`const tempDir = await mkdtemp(...)` déclaré hors du bloc `try`. Si `mkdtemp` échoue, la `const` est en Temporal Dead Zone — le `finally` tente `rm(tempDir)` sur un binding non-initialisé → `ReferenceError` masquant l'erreur originale. Fix : `let tempDir: string | undefined` + guard `if (tempDir)` dans le `finally`. LRN-048.

### 4. TS2666 — `declare module` inline vs `.d.ts` séparé (BLK-010)

Un bloc `declare module "apngasm-bin"` placé dans un fichier avec des imports ES est traité comme une augmentation de module, non une déclaration ambiante. Résolu par la création d'un fichier `src/apngasm-bin.d.ts` sans aucun import. LRN-045.

### 5. Mauvaise classification defer — messages FR dans une lib publique

D4 en review 2.3 (messages d'erreur en français) initialement classé "defer — décision de design". Recadré immédiatement par Baptiste : l'anglais est une convention universelle pour une lib npm publique, pas une variable de design. Appliqué sur 3 modules en une passe. LRN-040, BDR-020.

## Insights clés

1. **La validation visuelle est irremplaçable pour les données empiriques.** Les frame counts Petdex ne peuvent pas être déduits de la spec — ils doivent être comptés manuellement sur les vraies spritesheets. Aucun test automatisé ne peut se substituer à cette étape.

2. **Les dépendances natives nécessitent une couche de vérification supplémentaire.** `apngasm-bin` a deux points de défaillance silencieux : postinstall non exécuté (BLK-011) et absence de garde runtime (D1 Story 2.4). La CI doit les couvrir explicitement.

3. **Un taux de résolution opportuniste de 44% est un signe de maturité.** Distinguer les trivials (applicables immédiatement) des defers légitimes évite l'accumulation de dette de review.

4. **Le pattern skeleton Dev Notes amortit le coût de conception à l'implémentation.** Chaque heure investie dans les Dev Notes d'une story économise du diagnostic à l'implémentation.

5. **Les tests de bytes ne valident pas le contenu visuel.** `acTL présent` ≠ `animation correcte`. Les deux doivent être vérifiés séparément sur des artefacts visuels.
