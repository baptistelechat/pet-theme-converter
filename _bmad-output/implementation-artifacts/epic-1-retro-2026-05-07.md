## Ce qui a bien fonctionné

### 1. Exécution fluide — 0 blocage d'implémentation

Les 3 stories ont été livrées sans blocage. L'Epic 1 était bien scoped : fondation simple, délimitée, livrable proprement. Le fait que ce soit un epic de fondation (configs, types, documentation) l'a rendu accessible et prévisible.

### 2. Pattern skeleton Dev Notes → zéro friction

Le copier-coller de skeletons complets dans les Dev Notes de story a éliminé toute friction d'implémentation. LRN-024 le documente : sur Story 1.2, 7 fichiers créés en une session, zéro blocage, build + typecheck verts du premier coup. Pattern à répliquer sur toutes les stories suivantes.

### 3. Détection précoce de `moduleResolution: "bundler"`

La correction de `"Node16"` → `"bundler"` en Story 1.1 a évité un blocage potentiellement coûteux en Epic 2 ou 3. Le learning LRN-013 et la décision BDR-012 sont documentés. TypeScript 5.x + tsup = `"bundler"`, pas `"Node16"`.

### 4. Résolution opportuniste pendant les reviews

4 findings déférés ont été résolus directement pendant les code reviews sans attendre une story dédiée :

- Check runtime Node.js dans `src/cli/index.ts`
- `external: ['sharp', 'apngasm-bin']` dans `tsup.config.ts`
- JSDoc complets sur les types publics (`src/types.ts`)

### 5. Code reviews denses avec bonne structure

La structure 3 couches (Blind Hunter, Edge Case Hunter, Acceptance Auditor) a fourni une analyse complète sur les 3 stories. Tous les ACs ont été validés. Les findings ont été bien triés (patch / defer / dismiss).

## Ce qui a été difficile

### 1. Graphify — mauvaise adéquation outil/contexte (friction majeure)

**Fait :** 5 itérations du graphe (v1 → v5) pour un projet 100% documentaire à ce stade. Abandon définitif en BDR-017.

**Impact :** Première et unique fois où Baptiste a atteint 100% de consommation de session Claude Code (5h). Le mode `--update` de graphify passe par le LLM pour re-labelliser les communautés modifiées — sur un projet sans code complexe, le coût est disproportionné.

**Root cause :** Graphify a de la valeur sur des codebases complexes avec de nombreux fichiers interdépendants. En Epic 1, le projet était composé de configs, stubs et documentation — pas de graphe utile à cartographier.

**Décision actée :** BDR-017 — arrêt définitif de graphify jusqu'à l'existence d'une codebase lourde et complexe (pas avant Epic 3/4 minimum).

### 2. Faux positifs en code review (~50% sur stories de config)

Le Blind Hunter génère environ 50% de faux positifs sur les stories de configuration, liés à la date de cutoff du modèle. Des packages parfaitement installés et fonctionnels (`typescript 6.0.3`, `@clack/prompts 1.3.0`) ont été flaggés comme "inexistants".

**Solution identifiée :** Utiliser `/find-docs` (Context7) proactivement pour alimenter le contexte avec les versions réelles — pas uniquement avant les reviews, mais systématiquement à chaque besoin de référence de version ou d'API. Ce comportement est désormais automatique côté agent (pas de déclenchement manuel requis).

### 3. `python3` vs `python` sur Windows (résolu)

Le stub Microsoft Store intercepte `python3` — les scripts BMAD échouaient à l'activation. Corrigé et documenté dans LRN-005. Règle : toujours utiliser `python` (sans le 3) sur cette machine.

## Insights clés

1. **Un epic de fondation ne mesure pas la complexité du produit** — il pose les rails. Le succès d'Epic 1 ne garantit pas Epic 2, qui introduit les premières dépendances natives complexes (`sharp`, `apngasm-bin`).

2. **Le coût de l'outillage doit être proportionnel à la valeur** — graphify consomme des tokens LLM à chaque update. Sur un projet jeune, c'est un luxe coûteux. Réévaluer quand la codebase est mature.

3. **`/find-docs` comme réflexe proactif** — pas un outil de dernier recours. Dès qu'une question de version, d'API ou de package émerge, l'agent le consulte directement sans attendre.

4. **Le STATE_MAPPING est un placeholder** — `frames: 9` et `row: 0-7` dans `src/core/state-mapping.ts` sont des stubs intentionnels. Story 2.2 doit les valider contre les vraies spritesheets avant tout traitement.
